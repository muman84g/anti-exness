## Sensitive Exclusions

For a first-time bot push, include the generated target bot folder as requested by project policy, excluding:

- `live_config.py`
- `startup.ini`
- direct live-config derivatives such as `__pycache__/live_config*.pyc`
- `.env`, credentials, account data, secrets, and tokens

If the user will test the new bot through Docker Compose, the first-time push must also include the target `exness-bot-<NN>` service in `docker-compose.yml`, the assigned service name in `BOT_BACKTEST_MAP_ja.md`, and README commands that use that exact service. If the compose service is intentionally not added, do not report a `docker compose run ... exness-bot-<NN>` command; give a non-service command or state that compose service creation is still required.

For an existing bot update, stage only the authorized changed files unless the user asks to refresh the whole target folder.

## CentOS Follow-Up

After a successful push, report these target-specific next steps; do not run them unless separately authorized on that host:

```bash
cd /home/muu/python_program/anti-exness
git pull
```

For this CentOS Docker deployment, treat `git pull` as host-file update only.
If live-bot source, params, artifacts, compose mounts, or helper files changed,
the running container should be considered stale until the target service is
recreated. Do not say the running bot has the update just because `git pull`
finished.

The local source folder already contains the sensitive files `botNN/live_config.py` and `botNN/startup.ini`. They are intentionally excluded from Git. After `git pull`, upload both files manually into the same `botNN` folder on CentOS before any compose `run` or `up`. A bind mount whose source file does not exist can create that path as a directory on the host; then SCP upload fails with `is a directory`.

Folderized sensitive-file check and repair:

```bash
cd /home/muu/python_program/anti-exness
for name in live_config.py startup.ini; do
  test -e "bot<NN>/$name" && ls -ld "bot<NN>/$name" || true
done

# If either path is a directory, stop the target and rename only the mistaken path.
for name in live_config.py startup.ini; do
  if [ -d "bot<NN>/$name" ]; then
    sudo docker compose stop exness-bot-<NN> || true
    mv "bot<NN>/$name" "bot<NN>/${name}.dir_backup_$(date +%Y%m%d_%H%M%S)"
  fi
done

# Upload the real local files now, then require both to be regular files.
test -f bot<NN>/live_config.py && test -f bot<NN>/startup.ini && echo "sensitive files are regular files"
```

Do not substitute `startup.example.ini` or `live_config.example.py` for actual login files. Compose must mount `./bot<NN>/startup.ini:/app/startup.ini:ro`; this prevents an old login baked into an image from being used silently. Preserve login/server/password fields from the intended account config, and edit only explicitly authorized fields.
